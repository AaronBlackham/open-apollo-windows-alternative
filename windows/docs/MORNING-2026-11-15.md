# Morning install and tests, Nov 15 2026

Build: `builds\2026-11-15-am` (DriverVer 11/15/2026 6.36.16.306). Contains G5 (Twin X inputs), G6 (combined
device), G7 (combined Windows endpoints), plug-in hosting P0, monitor features (ALT, sources, cues, talkback),
the Apollo Control unit selector + Cues tab, and every review fix from the night.
Rules: short tests only; nothing contacts Universal Audio; Claude runs every elevated step, Aaron does the power
cycles, plugs in cables and answers what he hears.

## 0. Reboot (Aaron)
The x8p is marked "reboot required" (an app held its endpoints during a disable at G6), so no driver can load
before a PC reboot. Restart the PC, open VS Code **as administrator**, open the Avium folder, resume the session,
say "continue".

## 1. Install (Claude, no power cycle)
- Quit Apollo Control and Ableton.
- Save the Windows default devices; `pnputil /add-driver` the package; `devcon update` the x8p, then the Twin X.
- Register the new `avium-asio.dll` (it changed at G6/G7) and refresh the verified tool copies (manifest).
- Restore the defaults. Check both units Connected on 6.36.16.306.
- Twin X unit key for the first cold start: G5 dry run (`StripsEnable=2`, `StripSteps=0`, `StripMask=3`,
  `StripDsp=1`, `MixerInitBatch=1`, `EnabledEndpoints=0xF`).

## 2. Front panel check (Aaron)
The Twin X readback says 48V ON and LINK ON for inputs 1-2, both at 40 dB. Compare with its front panel before
anything touches 48V or link. If it disagrees, the Gen 1 readback decode is wrong: stop and fix that first.

## 3. Power cycle 1: both units (Aaron)
Twin X monitor knob down, headphones low. Twin X off, x8p off, wait 10 s, x8p on, Twin X on.
Gives: x8p cold (strips Live), Twin X cold with the G5 dry run.

## 4. Tests that need no further power cycle (Claude)
- `step-g5.ps1` run 2: dry-run checks; on pass it sets `StripsEnable=1`.
- `step-p1.ps1 -Step licence`: reads the licence table on the x8p (no internet, from the unit). Then, if a mapped
  plug-in is licensed (SuprEsser, DMX 15-80 S, RMX16, RMX16 Expanded or C-Vox): `-Step plain` (unrouted on DSP 2),
  then `-Step start` (input 1, mono, 60 s). Aaron: something plugged into inputs 1-2 (the Sphere's two outputs
  ideally). PluginHost goes back off at the end.
- `step-mon.ps1` (about a minute): ALT, sources, cues. Warning: ALT/source toggles move audio between speakers.

## 5. Power cycle 2: Twin X only (Aaron)
Speakers off or the Twin X knob down (a live strip feeds the monitor mix). Then `step-g5.ps1` run 3: live strips;
Aaron plugs a mic into Twin X input 1, then input 2 (says if it needs 48V; never 48V on a ribbon), then an
instrument into the Hi-Z jack. An empty jack reads exact zero, so only zero with sound going in is a finding.

## 6. Power cycle 3: both units, G7 (Claude, then Aaron)
`step-g7.ps1` pass 1 (saves defaults, sets `EndpointSet=1`); power cycle both; pass 2: endpoint names, a 20 s
Windows loop, and the Windows + DAW sum test (about 50 s of tones). Then Aaron picks his default devices.

## If something goes wrong
- Twin X misbehaves: `revert-unit.ps1 -Unit twinx` is the way back to UA's driver (local only; it starts nothing).
- Strips: `step-g5.ps1 -Rollback`. Combined endpoints: `step-g7.ps1 -Rollback`. Plug-ins: `step-p1.ps1 -Off`.
- A blue screen reboots the PC: relaunch VS Code as administrator and say "continue"; Claude reads the crash first.
